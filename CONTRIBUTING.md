# Как помочь

Проект в стадии разработки и тестирования: он открыт именно для того, чтобы его
тестировали. Ниже — чем конкретно можно помочь и как оформить находку.

## Самый нужный вклад — тестирование

Не нужен код, чтобы быть полезным:

1. Установка на чистый VPS (Ubuntu/Debian, Fedora или RHEL-подобный) одной
   командой из [README.md](README.md) и проход по базовому сценарию:
   `init` → `run` → systemd → подключение панели → добавление аккаунта →
   старт сессии → установка zip-плагина → экспорт и импорт состояния.
2. Отдельно полезны прогоны на нестандартных окружениях: Ubuntu 24.04 с
   AppArmor-ограничением user namespaces (плагинные песочницы там не работают
   из коробки), дистрибутивы без `bubblewrap`, VPS с прокси/НAT, хостинги с
   закрытым входящим трафиком.
3. Написание простого плагина по гайду
   [Как писать плагины](https://github.com/nechel12/lucrium-protocol/tree/main/packages/lucrium-plugin-sdk/docs/writing-plugins.md)
   — всё, где гайд неполный или врёт, это баг документации.

**Используйте тестовые учётные записи площадок.** Воркер работает с сессиями
продавца: ошибки в этой версии могут стоить банa, поэтому не подключайте
рабочие магазины.

## Как сообщать о проблеме

Заводите issue с воспроизведением: версия (`lucrium-worker --version` или коммит),
дистрибутив, вывод `systemctl status lucrium-worker`, шаги, ожидаемое и фактическое
поведение. Логи (`/var/lib/lucrium/logs/worker.log`, journald) присылайте после
проверки: **в них не должно быть pairing-токена, golden_key, access_token и
api_key** — воркер их не пишет, но чужие строки вставать могут.

Находки безопасности — отдельно и приватно, как описано в
[SECURITY.md](SECURITY.md). Не публикуйте их в issue, пока не будет патча.

## Если правите код

Требуемые проверки (CI их выполняет, и они обязаны быть зелёными):

```bash
uv sync
uv run ruff check .
uv run ruff format --check .
uv run mypy src     # strict
uv run pytest       # filterwarnings = error
```

- История в `main` линейная: PR нужно вести на rebase, merge-коммиты не принимаются.
- Изменения протокола панель ↔ воркер делаются в `lucrium-protocol`, модели
  отсюда переиспользуются, своих дублей не заводим.
- Любая правка, касающаяся плагинов, кредов или сокета панели, — с тестом:
  это те места, где регрессия стоит денег и аккаунтов.
- Форматирование и линт чинятся на месте: `uv run ruff check --fix . && uv run ruff format .`.

## Чего пока не нужно

Небольших «почини стиль» правок по всему репозиторию и новых фич из roadmap
(магазин плагинов, Docker-образ, телеметрия): они спланированы, и параллельные
реализации только мешают. Для обсуждения направления — сначала issue.
